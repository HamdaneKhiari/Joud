1. Où en est le projet aujourd'hui

Ce qui est fait

  • Architecture white-label opérationnelle : 4 publics (Primaire, Collège, Lycée, Adulte), un seul code source, verrouillage par variable d'environnement au build (EXPO_PUBLIC_LOCKED_AUDIENCE)
  • 6 modules pédagogiques fonctionnels avec contenu réel pour Primaire et Collège (vocabulaire, phrases, lecture, dialogues, jeux de mots, connecteurs)

  • Jamais buildé via EAS (eas build) — seulement des builds de développement locaux
  • Signature de production Android non configurée (utilise encore le keystore de debug)

Résumé

Joud est conçue pour minimiser la collecte de données. L'app ne dispose d'aucun compte utilisateur, d'aucun serveur, et ne transmet aucune donnée personnelle à Joud ou à un tiers dans son usage normal.

Fonctionnalité IA (Tuteur IA) — la seule qui transmet des données

Joud propose un Tuteur IA optionnel. Cette fonctionnalité fonctionne selon un modèle "apporte ta propre clé" (BYOK) : l'utilisateur doit fournir sa propre clé API d'un fournisseur (OpenAI, Mistral ou Anthropic/Claude). Quand cette fonctionnalité est utilisée :

  • Les messages tapés par l'utilisateur sont envoyés directement depuis l'appareil vers le fournisseur choisi — Joud n'a pas de serveur intermédiaire et ne voit jamais ce contenu
  • Le traitement de ces données est soumis à la politique de confidentialité du fournisseur choisi (OpenAI, Mistral ou Anthropic), pas à celle de Joud
  • Cette fonctionnalité n'est jamais accessible sur le public Primaire (enfants) — aucune donnée n'est envoyée à un tiers pour ce public, sur aucun écran de l'app

Ce que Joud ne fait pas

  • Pas de compte, pas de connexion, pas de synchronisation cloud
  • Pas de publicité, pas de SDK publicitaire
  • Pas d'analytics ni de tracking (aucun SDK de mesure d'audience)
  • Pas de partage de données avec des tiers, hormis l'appel direct au fournisseur IA si l'utilisateur configure cette fonctionnalité (non disponible pour les enfants)
